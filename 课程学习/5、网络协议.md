# 网络模型

### 物理层
```
IEEE 802.3 ：以太网物理层规范
网线接口RJ145，光纤标准、rs-232
0和1原始比特流
```
### 数据链路层
```
局域网物理寻址 通过arp寻找目标mac地址
vlan隔离技术（IEEE 802.1Q）虚拟局域网标签协议
```
### 网络层
```
跨网段寻址，路由转发  封装源ip地址和目标ip在包中
ipv4/ipv6
icmp
ospf
ipsec
```
### 传输层
```
tcp udp 由操作系统随机分配本地源端口，并记录目标端口
可靠传输tcp
     三次握手，四次挥手
不可靠udp
```
### 会话层
```
web开发中的cookie/session机制
```
### 表示层
```
tls/ssl：提供数据加密
数据格式：json、xml、jpeg等媒体格式
加密算法：对载荷处理的算法，aes，rsa等
```
### 应用层 
```
http
dns
ftp
smtp/pop3/imap 电子邮件收发协议
websocket： 基于tcp的全双工通信协议
获取应用程序需要发送的业务信息，如http请求报文
```
# http特性

http协议为以下几大类：opitons、get、post、put、delete。
传参模式
1. 字符传参
    test?name=11&age=12
2. json方式
   服务端要求你传递json格式，那么你传递的数据，就必须按照他的要求来
```
{

"code": "",

"password": "",

 "phone": "",

 "username":"test"

 }
```

# http请求完整拆解


```
POST /api/v1/login HTTP/1.1              <-- 【1. 请求行】请求方法(POST) + 请求路径 + 协议版本
Host: api.example.com                    <-- 【2. 请求头】目标服务器的域名或 IP
Content-Type: application/json           <-- 【2. 请求头】极度重要！告诉服务器肚子里的数据是 JSON
Content-Length: 39                       <-- 【2. 请求头】告诉服务器数据的精确字节数，防止读取截断
User-Agent: Mozilla/5.0 (Windows NT)     <-- 【2. 请求头】客户端自报家门（浏览器及系统信息）
Connection: keep-alive                   <-- 【2. 请求头】告诉底层 TCP 发完别急着断开
                                         <-- 【3. 空  行】绝对不能少！服务器靠它判断 Header 结束
{"username":"test","password":"123"}     <-- 【4. 请求体】实际传递的业务数据，格式必须与 Content-Type 匹配
    
  
    
//返回    
HTTP/1.1 200 OK                          <-- 【1. 状态行】协议版本 + 状态码(200) + 状态描述(OK)
Date: Mon, 06 Jul 2026 10:00:00 GMT      <-- 【2. 响应头】服务器生成这个响应的绝对时间
Server: nginx/1.24.0                     <-- 【2. 响应头】服务器使用的 Web 软件及版本
Content-Type: application/json           <-- 【2. 响应头】告诉客户端，返回的数据也是 JSON 格式
Content-Length: 42                       <-- 【2. 响应头】返回数据的精确字节数
                                         <-- 【3. 空  行】(CRLF) 响应头结束的绝对分界线，下面就是正文了
{"code": 200, "msg": "登录成功"}          <-- 【4. 响应体】前端代码真正关心并提取的业务数据 


HTTP状态码：
200 请求成功了

302 跳转，让浏览器跳转

400 系列错误，都是客户端这边的错误比如405，你没有按照他的要求来请求，404找不到这个路径，本来就不存在这个资源

500 系列错误，都是服务端这边的错误
```
