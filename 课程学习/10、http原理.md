# http协议

```
通过服务端发送请求，获取资源信息
分为以下几种请求方式

GET     请求用于获取数据的
POST    请求用于保存数据的
PUT     请求用于修改数据的
DELETE  请求用于删除数据的
OPTION  这是一个预检请求
以上这种方式称之为rest风格
大部分还是用get和post

#http协议的特性，是一个单工的通信方式

1、用户发起请求
2、访问域名，首先查dns服务器，查看域名绑定的ip，或直接访问ip的网址
3、找到ip，然后根据端口访问，总共65535个端口
4、请求找到服务器后，web服务器根据请求返回对应数据

#http状态码
200 表示成功的意思
302 表示跳转的意思，如果请求返回302表示告诉浏览器你应该进行跳转
400 类的错误，一般表示客户端这边有问题
500 类错误，表示服务端有问题


# https  而不是 http

# 其实https也是http协议，只是他加了ssl证书，也就是传输数据的时候进行了加密，所以他就被叫做httpssl  简写https

# 没有安装ssl证书的，就叫http

# https 他其实监听的是443端口，我们访问的时候，默认还是走的80端口，但是我们有证书，所以当用户访问80端口的时候，我们用nginx将它进行跳转了到了443端口，所以我们现在网页上面显示https，说明我们现在访问的是服务器的443端口

  
  
  

# 鉴权

# 什么是鉴权呢？

# 当用户访问我们的服务的时候，web服务器，根本不知道是谁在和他连接。

# 所以我们需要一个鉴权信息，用来告知服务器，我是谁，我能看什么

  

# 早期的鉴权使用的是cookie/session

# 网页，由于一些信息比较敏感，不能给所有人都看，所以需要你登录后才能看，那么你登录后，服务端会执行什么呢？

# {"key":"你的个人信息"}  服务器会在你登录后，将你的信息存入到一个字典中，然后返回一个key给你

# 然后下次访问的时候，将这个key放到请求的头部中，那么服务端就知道你是谁，原理就是他在你请求的时候，将你带来的这个key，拿去索引出具体的value 这里面就是你的信息，那么服务器就知道了你能不能访问这些页面

  
  

# token 也是一种鉴权方式

# jwt这些凭证

# jwt是什么东西呢？他也是一种鉴权方式，上面我们提到了cookie和session,但是这里jwt他并不是服务端创建了一个字典

# 他的构造是由3段数据组成      

# head.payload.sign

# head 里面放的是他采用了那种方式加密。

# payload 就是携带的信息

# sign 就是验签工具，他会将payload信息，通过head中的算法进行加密，然后跟在后面，服务端获取这个jwt凭证后，会将这个payload，再进行加密算一次，和当前携带的sign进行比对，就可以得知，这个票据是否真实
```
