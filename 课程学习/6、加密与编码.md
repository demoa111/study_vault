
# 常见算法分类

```
编码
base64、url、hex   只是格式转换
url：防止出现错误解析
base64：主要用于二进制流转成文本形式，方便传输，比如在一个通信通道中，只允许传输文本协议，那么我们想传递一张图片，但是图片又是二进制的文件，就可以使用他将图表编码成base64格式，然后接收方再将其转换回来，得到图片。
hex：16进制的表示符，16进制为0-F组成的数字表示信息，方便处理数据。
```

```
加密 （对称加密）
aes、des、chacha20 速度快，适合加密大文件，只有一把钥匙，由该钥匙加解密
缺点：只能用这把钥匙解，一旦泄露就没有意义了。
```

```
加密（非对称加密）
rsa、ecc   安全度极高，适合加密秘钥或数字签名
有两把钥匙，公钥和私钥
公钥解密----私钥加密
私钥解密----公钥加密
一般用途：
    		1.高安全性网站，会使用他进行加密数据，比如一些网站你抓包会发现他全加密的，这个就是采用非对称加密，前端会有一个公钥，每次收到服务器返回则使用公钥解密，然后发送数据使用公钥加密。
    		2.数字签名：我将公钥公布给所有人，但是我自己掌握私钥，我发布一个私钥加密的字段，其他人使用公钥解密开，能解密成功，说明这个数据是我用我的私钥加密的，确保这个信息是我设定的，以此来鉴定信息的真实可靠性
```

```
哈希
md5、sha-256、bcrypt   不可逆 常用于存密码或文件防篡改
	哈希并非加密，只是通过当前的数据，算出一串唯一的信息，该信息无法解密为原文。
	任意大小的文件，进行hash后都会得到一个固定长度的字符串  
	
	缺点是唯一性，为了防御攻击者md5加盐。
	
	
	Bcrypt 一般是spring的安全框架都会使用这个进行hash  
```

### 关于加密或hash后面的数字是什么意思

```
如果你尝试过自己搭建通信通道，就会看到各种SHA-256 SHA-512等，这些是什么呢？

1. 在哈希算法中，数字代表输出结果的长度

   SHA-256：不管你输入的是一个字还是一部 100GB 的电影，算出来的哈希值永远是 256 个 bit。

   SHA-512：同理，输出永远是 512 个 bit。数字越大，碰撞（重复）概率越低。

2. 在对称加密 (如 AES)中，数字代表密的长度

   AES-128：代表用来锁保险箱的这把“钥匙”长度是 128 bit。

   AES-256：钥匙长度是 256 bit。256 位的破解难度极高，目前人类算力无法暴力破解 AES-256。

3. 在非对称加密 (如 RSA)中，数字代表大整数因数分解的长度

   RSA-2048 / RSA-4096：RSA 的钥匙特别长，2048 代表密钥位数为 2048 bit。目前行业最低安全标准就是 RSA-2048。

```

  
  
  

### 常见的哈希和加密及应用场景

  

```
编码家族：Base64（常用于 JSON 传图片/JWT Token）、URL Encoding（网址传参防歧义）。

哈希家族：MD5、SHA-256（目前主流）、Bcrypt（自带加盐，密码存储之王）。

对称加密：AES（地球上最快、最安全的对称加密，日常 HTTP 底层数据加密全靠它）。

非对称加密：RSA（稳定可靠，用于 HTTPS 握手交换密钥）、ECC（新一代霸主，比特币钱包和现代证书大量使用）。
```
